# 進貨流程使用說明

這份說明給已經安裝好本工作包的同事使用。目標是把廠商進貨單、銷貨憑單或送貨單交給 Codex，讓 Codex 協助完成 OCR、產品比對、覆核、建檔用檔案與採購匯入檔。

## 使用前確認

開始前先確認：

- 已用本 repo 完成安裝，並已重開 Codex。
- 電腦有桌面版 Microsoft Excel；最後輸出舊版 `.xls` 會用到 Excel。
- 今天的 `產品資料輸出.CSV` 已放在：

```text
%USERPROFILE%\Documents\大統工作助手\參考資料
```

若產品資料不是今天的版本，產品比對流程會停下來提醒更新，不要跳過這個檢查。

## 最簡單使用方式

在 Codex 裡上傳或指定進貨單圖片，並貼下面其中一句：

```text
這是進貨單，請幫我跑進貨流程。
```

或：

```text
請用 convert-vendor-invoice-image 處理這張廠商銷貨憑單。
```

如果圖片已經在資料夾裡，可以貼：

```text
請處理這張進貨單：
C:\Users\你的帳號\Documents\大統工作助手\廠商進貨單\檔名.jpg
```

## 流程會做什麼

Codex 會依序做這些事：

1. 判斷圖片是不是進貨單、銷貨憑單或送貨單。
2. 用本機 OCR 讀取品名、數量、進價、金額與總額。
3. 輸出可覆核的原始進貨明細 `.xlsx`。
4. 用目前產品資料比對已建檔商品、相似商品與新品候選。
5. 需要人工判斷時，輸出待確認清單讓你回覆。
6. 你確認產品代號、正式名稱與大類後，產生正式調整檔。
7. 產生建檔用 `.xls` 與採購單匯入 `.xls`。
8. 核對採購單逐筆 `數量 × 單價` 與總額。
9. 正式成品驗證通過後，把來源圖片加上 `_已處理`。

## 你需要確認的停止點

流程不是全自動到底，以下情況 Codex 會停下來等你確認：

- OCR 看不清楚品名、數量、進價或金額。
- 單筆金額不等於 `數量 × 進價`。
- 商品金額合計不等於單據總額。
- 發現相似商品，可能已建檔但不確定。
- 發現新品，需要你提供產品代號。
- 正式名稱或大類需要人工調整。
- 廠商名稱或廠商代號無法確認。
- Excel、範本或檔案權限有問題。

停下來時，先看 Codex 列出的疑點，不要直接叫它猜。進貨資料錯一次，後面建檔與庫存都會跟著錯。

## 回覆產品確認資料

Codex 需要你確認新品或待修正商品時，通常會要求你貼回 TSV。可以直接用下面格式：

```text
產品代號	正式名稱	大類
015123	(景品)蒙其D.魯夫-航海王KING OF ARTIST	39
015124	(盲盒)Pingu搞怪時刻米粒公仔@12	34
```

注意：

- 產品代號請保留六位數，例如 `014796`，不要變成 `14796`。
- 大類可填代號即可，例如 `39`；也可填 `39 景品`。
- 如果某列不是這次要建檔或採購的商品，請明確說明要排除。
- 不同廠商的進貨單不要混在同一張採購單。

## 產出檔案位置

流程檔案預設會放在：

```text
%USERPROFILE%\Documents\大統工作助手\建檔進貨用
```

常見產出包含：

- OCR 原始進貨明細 `.xlsx`
- 產品比對檢查 `.xlsx`
- 產品確認後的調整 `.xlsx`
- 建檔用 `.xls`
- 採購單匯入 `.xls`

真正要匯入系統的是最後的建檔用與採購單匯入 `.xls`，中間 `.xlsx` 是給覆核與重跑用。

## 完成時要看什麼

Codex 完成後，請確認回報有包含：

- 建檔用檔案路徑。
- 採購單匯入檔案路徑。
- 建檔筆數與採購筆數。
- 採購總額。
- 是否逐筆核對 `數量 × 單價`。
- 來源圖片是否已改成 `_已處理`。
- 本次是否有流程優化建議。

如果 Codex 只說「檔案已產生」，但沒有總額核對或筆數資訊，請要求它補驗證。

## 常用指令

檢查安裝是否正常：

```text
請幫我檢查大統進貨流程安裝是否正常。
```

處理新進貨單：

```text
請處理這張進貨單，先 OCR，等我確認疑點後再繼續建檔與採購檔。
```

繼續上一張卡住的進貨單：

```text
請從上次進貨流程的狀態繼續，不要重跑已完成階段。
```

只做產品比對：

```text
請用目前產品資料比對這份進貨明細，先輸出產品比對檢查檔。
```

只做正式匯入檔：

```text
我已確認產品代號、正式名稱與大類，請產生建檔用與採購單匯入檔，並核對總額。
```

## 常見問題

### Codex 說產品資料不是今天的版本

請先從系統匯出最新 `產品資料輸出.CSV`，放到：

```text
%USERPROFILE%\Documents\大統工作助手\參考資料
```

再請 Codex 重跑產品比對。不要叫 Codex 忽略產品資料日期。

### OCR 結果看起來怪怪的

請要求 Codex 停在 OCR 原文確認，列出可疑列。必要時補拍清楚一點的圖片，尤其是品名、數量、進價、金額欄位。

### 相似商品不知道是不是同一個

不要讓 Codex 自行決定。請看產品名稱、版本、平台、款式、尺寸、入數、角色與廠商貨號，確認後再回覆是已建檔或新品。

### Excel 無法輸出 `.xls`

最後正式建檔與採購匯入需要桌面版 Excel。如果沒有 Excel，OCR、比對與中間 `.xlsx` 仍可做，但正式 `.xls` 要換到有 Excel 的電腦完成。

## 使用原則

- OCR 有疑點先確認，不猜。
- 相似商品先確認，不自行併入已建檔。
- 廠商不確定先停，不自行猜廠商代號。
- 採購單完成後一定看總額。
- 正式成品驗證通過後，來源圖片才會加 `_已處理`。
